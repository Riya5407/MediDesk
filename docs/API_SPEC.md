# MediDeck API Specification

Internal pharmacy management API for MediDeck. Built with **FastAPI** and **psycopg 3** (raw SQL, connection pooling, no ORM).
Base path: `/api`. All request bodies and responses are JSON. Field names match database column names (`snake_case`).

---

## 1. Global Rules & Security

**Config (env, never hardcoded):** `DATABASE_URL`, `JWT_SECRET`, `ENVIRONMENT`, `AUTH_ENABLED`, `COOKIE_SECURE`, `LOW_STOCK_THRESHOLD=20`, `EXPIRY_WARNING_DAYS=30`, `PAYMENT_MODES=Cash,Card,UPI`, `CORS_ORIGINS`, `FORWARDED_ALLOW_IPS`.

**Dates:** ISO `YYYY-MM-DD`. "Today" is the server date.

**Pagination (list endpoints):** `?page=1&page_size=20` (max 100).
Standard pagination response:
```json
{
  "items": [...],
  "total": 123,
  "page": 1,
  "page_size": 20
}
```

**Errors:** always `{ "detail": "human readable message" }`. Mapping from PostgreSQL & application errors:

| Cause | HTTP | Notes |
|---|---|---|
| Trigger `RAISE EXCEPTION` (`P0001`) | 400 | Pass the trigger's message through unchanged (e.g. "Insufficient stock in batch 12") |
| Check violation (`23514`) | 400 | Friendly message naming the field |
| Foreign key violation on delete (`23503`) | 409 | "Cannot delete: this record is in use" |
| Unique violation (`23505`) | 409 | "Already exists" |
| Row not found | 404 | "Record not found" |
| Request validation failure | 422 | FastAPI standard detail array |
| Authentication failure / Token expired | 401 | "Invalid credentials" or "Token has expired" |
| CSRF validation failure | 403 | "CSRF token missing or invalid" |
| Insufficient role permissions | 403 | "Access forbidden: insufficient role permissions" |
| Rate limit exceeded | 429 | "Too many failed login attempts. Please try again later." |

**Transactions & Triggers:**
- Every write that touches more than one table runs in a single database transaction.
- Primary keys and identity columns are generated by the database; the API never supplies them.
- Medicine stock (`qty_in_stock`) and bill totals (`total_amt`) are maintained exclusively by database triggers. Application code must NEVER write or overwrite these values.

**Derived statuses (computed in SQL, never stored):**
- **Batch `status`** (first match wins):
  1. `expired` (`exp_date < today`)
  2. `out_of_stock` (`qty_in_stock = 0`)
  3. `expiring_soon` (`exp_date <= today + EXPIRY_WARNING_DAYS`)
  4. `low_stock` (`qty_in_stock <= LOW_STOCK_THRESHOLD`)
  5. `in_stock`
- **Medicine `status`** uses `total_stock` = sum of `qty_in_stock` over non-expired batches:
  1. `out_of_stock` (`total_stock = 0`)
  2. `low_stock` (`total_stock <= LOW_STOCK_THRESHOLD`)
  3. `in_stock`

## 2. Authentication & Authorization Flow

### Authentication Architecture
- **JWT Cookies**: On successful login, the server issues an HTTP-only `access_token` cookie and a readable `csrf_token` cookie.
- **CSRF Protection**: For state-changing operations (`POST`, `PUT`, `PATCH`, `DELETE`), clients authenticating via cookies must submit the CSRF token in the `X-CSRF-Token` request header.
- **Bearer Token Support**: The `Authorization: Bearer <token>` header is also accepted for programmatic API access.
- **Rate Limiting**: Login endpoint enforces rate limits on failed authentication attempts tracked per client IP (proxy-aware) and per username (max 5 consecutive failures before temporary cooldown).

### Endpoints

| Method | Path | Auth | Roles | Description |
|---|---|---|---|---|
| POST | `/auth/login` | None | Public | Accepts `{ "username": "...", "password": "..." }`. Sets auth cookies and returns session info. |
| GET | `/auth/me` | Required | All | Returns current user `{ "username": "...", "role": "..." }`. |
| GET | `/auth/verify` | Required | All | Validates active session token. Returns `{ "valid": true, "username": "...", "role": "..." }`. |
| POST | `/auth/logout` | Optional | All | Clears `access_token` and `csrf_token` cookies. |

## 8. Point of Sale & Sales

**POS Search**
`GET /pos/medicines?q=para&limit=20` returns:
`[{ med_no, med_name, unit, mrp, total_stock, batches: [{ batch_no, exp_date, qty_in_stock }] }]`
Only sellable batches are included (`exp_date >= today` and `qty_in_stock > 0`), ordered by `exp_date` ascending so the oldest stock sells first (FIFO). Medicines with no sellable batch are omitted.

**Create Bill**
`POST /sales` body:
```json
{
  "cust_no": 5,
  "emp_no": 2,
  "payment_mode": "Cash",
  "lines": [
    { "med_no": 1, "batch_no": 10, "qty_sold": 2, "sale_price": 12.5 }
  ]
}
```
- `cust_no` may be null (walk-in). `emp_no` and `payment_mode` required. `payment_mode` must be one of `/meta` payment_modes.
- `sale_price` optional; omitted means trigger defaults to medicine MRP. A lower price represents a discount.
- Inserts into `sale` (sale_date = today), then lines into `sale_details`, in one transaction. Database triggers deduct stock and compute `total_amt`.
- Returns 201 + Sale detail.

**Sale Detail Object:**
`{ bill_no, sale_date, cust_no, cust_name, emp_no, emp_name, payment_mode, total_amt, lines: [{ med_no, med_name, batch_no, qty_sold, sale_price, mrp, discount_pct, line_total }] }`

| Method | Path | Roles | Notes |
|---|---|---|---|
| GET | `/sales` | All | Query: `from`, `to`, `search` (bill number or customer name), `page`, `page_size`. Newest first |
| GET | `/sales/{bill_no}` | All | Full sale detail |
| DELETE | `/sales/{bill_no}` | Admin Only | Cancels the bill: deletes lines first (trigger restores stock), then sale record, in one transaction |

## 11. Purchase Orders

**Purchase order object:** `{ pur_no, sup_no, sup_name, order_date, status, total, lines: [{ med_no, med_name, qty_ordered, rate, line_total }] }`
(`status` is one of `Pending`, `Delivered`, `Cancelled`.)

| Method | Path | Roles | Notes |
|---|---|---|---|
| GET | `/purchase-orders` | Admin, Pharmacist | Query: `status`, `sup_no`, `from`, `to`, `page`, `page_size`. Newest first |
| GET | `/purchase-orders/{pur_no}` | Admin, Pharmacist | Full object with lines |
| POST | `/purchase-orders` | Admin, Pharmacist | Body: `{ sup_no, lines: [{ med_no, qty_ordered, rate }] }`. Created as `Pending` |
| PATCH | `/purchase-orders/{pur_no}/status` | Admin, Pharmacist | Body: `{ "status": "Cancelled" }`. Allowed only from `Pending` |
| POST | `/purchase-orders/{pur_no}/receive` | Admin, Pharmacist | Intake order: inserts batches and marks `Delivered` in one transaction |

**Receive Order body:**
```json
{
  "lines": [
    { "med_no": 1, "mfg_date": "2026-09-01", "exp_date": "2028-09-01", "qty_received": 100 }
  ]
}
```
